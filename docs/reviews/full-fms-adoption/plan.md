# SDK 0.4 full-FMS delivery plan

Owner direction: apply full FMS across the SDK, retain independent provider,
store and queue contracts, use published Get Modular and shared Foundation,
and complete reviewed delivery without treating older evidence as current.
This succeeds the earlier SDK-specific FMS deferral in historical design reviews.

## Delivery slices

1. Adopt the exact standard and complete feature census for all four packages;
   keep genuine semantic owners, inward dependencies and curated public exports.
2. Separate application read snapshots from provider/storage SPIs, retain
   immutable operation identity and complete concurrency checks, and replace
   exposed selection read sets with target-bound opaque versions.
3. Use published Get Modular modules, inputs, entries, groups, Resources and
   optional Observation. Validate the real layout and preserve physical shutdown.
4. Execute Foundation source/dependency/coverage/suppression checks, strict
   compiler and typed lint, with rejecting fixtures for actual bypass risks.
5. Qualify official Paddle SDK fixtures, subscriptions and independent credits,
   real PostgreSQL, interchangeable transactional queues and clean installed
   consumers on both admitted Node floors. Keep live-account deployment separate.
6. Register the repository centrally with explicit ownership and honest
   qualification status; provide reusable new-repository bootstrap enforcement.
7. Push reviewable checkpoints, complete independent critiques and fixes, then
   merge only after the actual required checks and protected-source transition.
