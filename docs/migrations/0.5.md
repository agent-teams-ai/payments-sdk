# Migrating to SDK 0.5

The owner permits breaking changes before deployed consumer adoption. All four packages
advance together. No deprecated overload or compatibility facade is retained. Persisted
payment identities, immutable evidence, unknown operations and consumer receipts remain
owned by their existing contracts; changing a TypeScript API never authorizes replaying
an uncertain external mutation or deleting payment history.

## Buyer and operator reads

Replace buyer reads with an explicit record:

```ts
await payments.readOperation({ operationId, buyerId: authenticatedBuyerId });
```

The runtime validates both identifiers even for JavaScript callers and snapshots them
before asynchronous storage access. Missing identity rejects before any store lookup;
a different buyer receives no operation. Never accept `buyerId` from the request body.

A trusted worker or operator selects `inspectOperation(operationId)` from the processing
surface. The Get Modular read facet contains no such method. The plain runtime remains
a Host-level combination of capabilities, not a sandbox or authorization server: expose
only the capabilities needed by each client.

## Deferred work and physical capacity

`PaymentRuntimeOptions.maxConcurrentMutations` defaults to 32 and accepts integers
1–1024. The permit is reserved before awaiting the durable dispatch marker. Marker
failure/conflict releases the permit without a provider call. A sent operation retains
its permit through physical provider completion and attempt settlement, even after the
caller's deadline returns `outcome_unknown`.

Handle the new `OperationResult` member:

```ts
{ kind: 'deferred', operationId, reason: 'mutation_capacity' }
```

It denotes a durable **prepared** operation with no attempt/dispatch marker yet. Do not
turn it into a new purchase request. The existing worker or trusted Host may execute the
same operation later. A custom Host without workers owns this scheduling. Deferred work
stays pending and does not consume the logical failure/quarantine budget. No unbounded
in-memory waiting queue is introduced.

This is a per-runtime bound on mutation dispatches, not an HTTP rate limiter, a bound
on all read requests, or a shared account/IP quota. Hosts sharing one provider quota must
coordinate their own ingress/work budgets. Lifecycle diagnostics expose both the configured
capacity and current admitted count. Closing still waits for physical work; do not close
a borrowed pool merely because a caller stopped waiting.

## Retry advice

Known rejected provider results may include `retryAt`, a bounded absolute ISO timestamp.
The official Paddle adapter translates its SDK's numeric Retry-After seconds once, at
receipt. Stored/read results retain the same instant instead of extending it on reread.
Malformed/negative/unsafe values are omitted. An unrecognized mutation error remains
`outcome_unknown` even if it contains a Retry-After header.

This advice does not change request idempotency, authorize automatic mutation retries,
replace a durable audited resolution, or expose raw provider diagnostics to buyers.

## Get Modular and packages

Use one coherent 0.5 SDK package set. Configuration, Checkout and Management descriptors
advance to revision 2; Read and Processing to revision 3; Delivery stays at revision 1.
These revisions cover the full declared value types, including changed operation-result
unions. Recompile the real complete descriptor maps and installed consumers. No upstream
Get Modular runtime release or accepted ADR is changed by this migration.

## Qualification boundary

Focused negative controls must reject the old optional-buyer API, demonstrate that a
caller deadline does not release physical capacity, and show no duplicate dispatch after
worker restart/retry. Supported Node 24/26 full CI, real PostgreSQL deferred-work handling,
official Paddle SDK rate-limit fixtures and strict installed consumers remain mandatory.
Actual account credentials, high-load sizing and central GitHub administration are separate
qualification scopes. This guide does not assert they have been completed.
