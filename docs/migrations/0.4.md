# Upgrade to 0.4

Upgrade all four Payments packages together. This deliberate 0.x minor release
separates application reads from mutable custody contracts and adopts full FMS
without requiring Get Modular in plain SDK consumers. Package versioning does
not establish npm publication; follow [release installation](../releasing.md).

## Import the capability you implement

Application commands, readonly results and neutral evidence remain in
`@agent-teams/payments-core`. Provider implementations import their port from
`@agent-teams/payments-core/provider`; storage implementations use
`@agent-teams/payments-core/store`. The test store remains in `/testing`.

```ts
import { createPayments } from '@agent-teams/payments-core';
import type { PaymentsRead, PaymentRuntimeOptions } from '@agent-teams/payments-core';
import type { PaymentProvider } from '@agent-teams/payments-core/provider';
import type { PaymentStore } from '@agent-teams/payments-core/store';
```

Use the explicit checkout, read, management, processing and delivery function
property contracts for injected capabilities. They preserve contravariant
parameter checking; replacement implementations cannot require stronger buyer
or checkout preconditions. The plain `createPayments()` factory composes the
same capabilities and retains Host-owned stop/drain controls.

## Treat reads as detached values

Replace public use of mutable `PaymentOperation`, `PurchaseIntent` and
`SubscriptionBinding` storage records with `PaymentOperationRead`,
`PurchaseIntentRead`, `SubscriptionBindingRead`, `PurchaseRead` and
`ObservedSubscriptionRead`. Public reads copy nested borrowed records and
exclude private dispatch, publication and reducer control fields. Do not mutate
a read to request a state transition; use the corresponding application command.
PostgreSQL recovery's `inspectUnknown` callback also receives
`PaymentOperationRead`.

## Refresh an audited selection before committing it

`readSubscriptionSelection(buyerId, bindingId, providerSubscriptionRef)` now
returns a target-bound opaque `version`. Pass it unchanged to
`selectSubscriptionStream` alongside buyer, binding, target subscription and
the required actor/audit/reason fields. Stop constructing or persisting internal
read-set tuples in application code.

The version is optimistic concurrency evidence, not authorization. The core
rechecks current buyer/target authority and the complete read set, and the
store retains complete commit-time CAS. A stale or differently scoped version
rejects; reread and review the current state before a new audited decision.
Do not automatically select another external stream after a conflict.

## Get Modular and infrastructure

Get Modular `Read` and `Processing` contracts advance to revision 2; other
contracts remain revision 1. Rebuild consumer bindings against the coordinated
SDK package versions. Keep one physical published Core/Assembly 0.7.0,
Resources 0.2.1 and, when used, Observation 0.2.0 peer set. Use the optional
`/observation` public entrypoint; hooks never perform durable financial delivery.

The generic PostgreSQL root still requires neither `pg` nor `pg-boss`.
Select `/node-postgres` and `/pg-boss` explicitly, or supply the existing
database/transactional transport contracts. Drizzle 1.0.0-rc.5 is private to
this PostgreSQL implementation. A different database engine still requires
its own store adapter and equivalent durability/concurrency evidence.

Persisted payment identities, evidence version 1, the physical schema and
transaction/recovery guarantees remain unchanged. Source topology migration
is not a database migration. Existing unknown external outcomes remain unknown;
upgrading never authorizes redispatch or a second charge.

## Contributor migration

Source is organized by concrete feature ownership, curated composition facades
and inward dependencies. Update private test imports to their owned source
facades and use curated `/testing` exports across packages. Run the complete
[Foundation/FMS profile](../foundation-adoption.md), packed consumers and both
runtime-floor gates. No SDK package is exempt from full FMS.
